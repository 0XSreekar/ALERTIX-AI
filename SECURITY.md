# Security Policy

## Supported versions

ALERTIX-AI is under active development. Security fixes are applied to the main branch. Users are encouraged to track the latest commit on main rather than older snapshots.

## Reporting a vulnerability

If you believe you have found a security vulnerability in ALERTIX-AI, please report it privately rather than opening a public issue. Public disclosure before a fix is available puts users of the early-warning system at risk.

To report, use the private vulnerability reporting feature on this repository, or contact the maintainer directly by email. Please include a description of the issue, the steps needed to reproduce it, the affected component such as backend, frontend or the ML pipeline, and the potential impact as you understand it.

You can expect an acknowledgement within a few days. Once the report is confirmed, a fix will be prepared and released, and you will be credited in the release notes unless you prefer to remain anonymous.

## Scope

In scope: authentication and authorisation flaws, injection vulnerabilities, exposure of secrets or credentials, insecure handling of citizen SOS data, and any issue that would allow an attacker to publish false hazard alerts.

Out of scope: vulnerabilities in third-party data providers, issues that require physical access to a user device, and reports generated by automated scanners without a working proof of concept.

## Handling of secrets

Never commit API keys, tokens or credentials to this repository. Use the .env file, which is excluded from version control, and refer to .env.example for the list of required variables. If a secret is committed by accident, rotate it immediately and report it so the history can be cleaned.

## Data privacy

SOS reports and any location data submitted by citizens are sensitive. Contributors must not log this data in plain text, must not include it in bug reports, and must not transmit it to third-party services beyond those already documented in the project.
